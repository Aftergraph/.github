# Aftergraph Support

Aftergraph is an open engineering and research organization. The fastest path to a useful answer is to route questions to the repository that owns the behavior or claim.

## Where to ask

| Topic | Repository |
|---|---|
| Agentic Institution Engineering, authority, delegation, revocation, conformance | https://github.com/Aftergraph/aie |
| SPEC-001, MISSION-Bench, research methods, replication, papers | https://github.com/Aftergraph/intelligence-systems-research |
| Runtime policy, approvals, audit chain, governed tool execution | https://github.com/Aftergraph/trust-gateway |
| Durable mission execution, WorkGraph, workers, leases, budgets, execution evidence | https://github.com/Aftergraph/works-execution |
| Work observation and WorkItem inference | https://github.com/Aftergraph/work-intelligence-v2 |
| Cross-repo contracts, terminology and claim boundaries | https://github.com/Aftergraph/after-graph-governance |

Use repository issues for reproducible bugs, feature requests, interoperability problems and documentation defects. Use the security process in `SECURITY.md` for vulnerabilities.

## When asking for help

Include the exact repository, commit or release, operating environment, command or API call, expected behavior, observed behavior and the smallest reproducible example you can provide.

For research questions, also state whether you are referring to deterministic testbed evidence, simulation, live-provider evidence, conformance evidence or independent reproduction. Those categories are intentionally not interchangeable.

## Not support channels

Do not place credentials, customer data, private logs or unreleased security findings in public issues. A screenshot of a terminal is also not a substitute for the command and output that created it. Humanity has tried this experiment extensively.
